# Инструкции для AI-разработки

## Перед изменениями

1. Прочитай `docs/PRODUCT_SPEC.md`, `docs/ARCHITECTURE.md` и текущий этап в
   `docs/IMPLEMENTATION_PLAN.md`.
2. Проверь `git status`; не перезаписывай чужие незавершённые изменения.
3. Выбери одну законченную задачу с проверяемым результатом.
4. Если решение меняет архитектуру или правила продукта, сначала добавь запись в
   `docs/DECISIONS.md`.

## Инварианты проекта

- Выбран только вариант «Лаборатория нестабильных порталов».
- Стек: React, TypeScript, Vite, React Context + `useReducer`, CSS Modules.
- Не добавляй backend, роутер или библиотеку состояния без подтверждённой
  необходимости.
- Бизнес-правила должны быть чистыми функциями в `src/domain/`, а не внутри JSX.
- Context координирует состояние; компоненты не должны самостоятельно менять
  доменные данные.
- Стили компонентов хранятся рядом с ними в `*.module.css`; глобально остаются
  только reset, токены и базовая типографика.
- Пользовательские тексты — на русском языке.
- Для времени в журнале используй внедряемый источник времени, чтобы тесты были
  детерминированными.
- Состояние LocalStorage валидируй и версионируй. Повреждённые данные не должны
  ломать запуск.
- Не храни секреты и токены в репозитории.

## Definition of Done для каждой задачи

- Выполнены критерии приёмки из плана или спецификации.
- Добавлены или обновлены тесты доменной логики и важных взаимодействий.
- Выполнены `npm run typecheck`, `npm run test:run` и `npm run build`.
- Обновлены чекбоксы плана.
- В `docs/AI_WORKLOG.md` добавлена честная краткая запись: вклад человека, вклад
  AI, суть промпта, исправления и доступная статистика. Не выдумывай время или
  токены — оставь явную пометку для владельца, если данных нет.
- Новое нетривиальное решение отражено в `docs/DECISIONS.md`.

## Приоритеты

1. Корректные правила и невозможные состояния.
2. Понятный основной сценарий за одну минуту.
3. Доступность и адаптивность.
4. Тесты, документация и только затем визуальная полировка.
