# Чеклист проверки

## Автоматические проверки

- [ ] Формула корректно классифицирует стабильный, опасный и критичный портал
  на границах 0%, 50%, 80% и 100%.
- [ ] `E = 0` и `K = 0` обрабатываются без `NaN` и деления на ноль.
- [ ] Энергия влияет на риск только через оставшееся время жизни.
- [ ] Портал получает количество существ из связанного мира.
- [ ] Нельзя создать 21-й открытый портал; закрытые не входят в лимит.
- [ ] Критичный портал без существ необратимо становится закрытым.
- [ ] Важность учитывает существ и все незакрытые порталы в тот же мир.
- [ ] Четвёртая попытка стабилизации за скользящий час запрещена; ровно через
  час попытка снова доступна.
- [ ] Неудачная стабилизация расходует попытку, но не меняет параметры портала.
- [ ] Успешная стабилизация не уменьшает время жизни на одной временной отметке.
- [ ] При максимальном бонусе стабилизация запрещена и попытка не расходуется.
- [ ] Наблюдатель повышает вероятность опасного портала и снимается после
  допустимой попытки.
- [ ] Наблюдателя нельзя отправить в критичный портал даже при выполнении всех
  остальных условий.
- [ ] Назначение наблюдателя снимается, если опасный портал становится
  критичным до попытки стабилизации.
- [ ] Успешные и отклонённые действия попадают в журнал.
- [ ] Сводка пересчитывается после изменения портала.
- [ ] Повреждённые данные LocalStorage не ломают приложение.

## Ручные сценарии перед сдачей

### 1. Пустой список

- [ ] Удалить/очистить демоданные доступным интерфейсным сценарием.
- [ ] Убедиться, что показано объяснение, а не пустой экран.
- [ ] Восстановить демоданные кнопкой.

### 2. Критический портал

- [ ] Открыть критический портал.
- [ ] Проверить процент риска, оставшееся время, физические параметры и
  рекомендацию.
- [ ] Убедиться, что статус явно обозначен текстом, а не только цветом.

### 3. Изменение состояния во времени

- [ ] Запомнить риск открытого портала.
- [ ] Выполнить управляемое обновление времени и коэффициентов.
- [ ] Проверить параметры, оставшееся время, новый риск, статус, сводку и журнал.

### 4. Выбор стабилизации

- [ ] Открыть важный опасный и важный критичный портал.
- [ ] Сравнить показанные шансы и решить, на какой портал потратить попытку.
- [ ] Проверить счётчик попыток после успеха и неудачи.
- [ ] Назначить наблюдателя очень важному опасному порталу и проверить повышение
  шанса.
- [ ] Попытаться отправить наблюдателя в очень важный критичный портал и
  проверить понятную причину отказа.

### 5. Автоматическое закрытие

- [ ] Довести портал до критичного состояния при наличии существ.
- [ ] Убедиться, что он не закрыт автоматически.
- [ ] Установить количество существ связанного мира в 0 доступным сценарием.
- [ ] Проверить необратимый переход портала в закрытое состояние.

### 6. Последовательность и сохранение

- [ ] Выполнить минимум три разных действия.
- [ ] Проверить порядок журнала.
- [ ] Перезагрузить страницу и убедиться, что состояние сохранилось.
- [ ] Сбросить демоданные.

## Финальный smoke-check

- [ ] `npm run typecheck`.
- [ ] `npm run test:run`.
- [ ] `npm run build`.
- [ ] Экран 320 px не имеет горизонтальной прокрутки страницы.
- [ ] Основной сценарий работает только с клавиатуры.
- [ ] AI Worklog доступен из основной навигации.
- [ ] README проверен на чистой установке.
- [ ] Публичное приложение открывается в инкогнито-окне.
- [ ] В репозитории нет секретов, `.env` и случайных токенов.
