# План работ

Оценка: **12–16 часов**, то есть один интенсивный или два обычных рабочих дня.
Порядок задач отражает зависимости. После завершения пункта нужно отметить его
чекбокс и выполнить указанные проверки.

## Этап 0. Подготовка — 1 час

- [x] Выбрать вариант «Лаборатория нестабильных порталов».
- [x] Зафиксировать стек: React, TypeScript, Vite, React Context, CSS Modules.
- [x] Нормализовать требования и архитектуру.
- [x] Зафиксировать уточнённую модель миров, порталов, времени жизни, риска и
  статусов.
- [x] Описать варианты ограниченной вероятностной стабилизации и наблюдателя.
- [x] Создать запускаемый каркас, тестовую среду и инструкции для AI.
- [x] Установить зависимости и зафиксировать `package-lock.json`.
- [x] Выполнить стартовые `typecheck`, тест и production-сборку.

Критерий приёмки: новый агент понимает задачу из файлов репозитория, а каркас
запускается стандартными npm-командами.

## Этап 1. Доменная модель — 2 часа

- [ ] Добавить отдельные типы мира, портала, риска, статуса и события.
- [ ] Реализовать связь портала с миром без дублирования количества существ.
- [ ] Реализовать внедряемый генератор порталов и лимит 20 открытых порталов.
- [ ] Реализовать эффективное рассеивание, оставшееся время и риск.
- [ ] Обработать `E = 0`, `K = 0`, границы риска и недопустимые числа.
- [ ] Реализовать переходы `stable` / `dangerous` / `critical` и необратимый
  `closed` через `wasCritical` и отсутствие существ.
- [ ] Реализовать рекомендации по уровню риска и состоянию.
- [ ] Реализовать селекторы важного и очень важного портала.
- [ ] После подтверждения коэффициентов реализовать общий скользящий лимит
  попыток, вероятностную стабилизацию и бонус наблюдателя.
- [ ] Запретить отправку наблюдателя в критичный портал и снимать назначение при
  переходе опасного портала в критичный.
- [ ] Согласовать масштаб времени, период обновления, расход энергии,
  инициализацию при нулевом рассеивании, состояние после схлопывания и эффекты
  пользовательских действий.
- [ ] Подготовить заданные миры и демопорталы со всеми статусами.
- [ ] Покрыть формулы, лимит генерации и переходы статусов unit-тестами.

Критерий приёмки: правила работают как чистые функции и не зависят от React.

## Этап 2. Состояние приложения — 1,5 часа

- [ ] Создать `PortalContext`, reducer и типизированные actions для миров и
  порталов.
- [ ] Реализовать выбор портала, фильтры, периодические обновления и уведомления.
- [ ] Хранить временные метки попыток и назначение наблюдателя в общем состоянии.
- [ ] Добавить журнал успешных и отклонённых операций.
- [ ] Реализовать версионированное сохранение в LocalStorage.
- [ ] Добавить безопасное восстановление демоданных.

Критерий приёмки: последовательность действий детерминированно меняет состояние,
а перезагрузка страницы его сохраняет.

## Этап 3. Основной интерфейс — 3–4 часа

- [ ] Собрать адаптивный каркас с навигацией «Порталы / AI Worklog».
- [ ] Добавить сводку: открытые, критические, закрытые, требуют внимания.
- [ ] Реализовать список с сортировкой по приоритету и фильтрами.
- [ ] Реализовать детальную карточку, объяснение риска и рекомендацию.
- [ ] Добавить согласованные действия и необходимые доступные подтверждения.
- [ ] Показать шанс успеха, доступные попытки и время восстановления попытки.
- [ ] Добавить журнал событий.
- [ ] Оформить компоненты через CSS Modules и общие design tokens.

Критерий приёмки: основной сценарий понятен за минуту и работает на ширине от
320 px без горизонтальной прокрутки страницы.

## Этап 4. Edge cases — 1–1,5 часа

- [ ] Реализовать пустое состояние и восстановление демоданных.
- [ ] Явно показать критический риск и его причины.
- [ ] Показать точную причину каждого запрещённого действия.
- [ ] Проверить изменение риска после обновления времени и коэффициентов.
- [ ] Добавить Error Boundary и сообщение о повреждённом хранилище.
- [ ] Сделать обязательные состояния быстро воспроизводимыми для проверяющего.

Критерий приёмки: все состояния из задания воспроизводятся без редактирования
исходного кода.

## Этап 5. Проверки — 2 часа

- [ ] Добавить не менее семи автоматических тестов из чеклиста.
- [ ] Проверить доступность основных действий с клавиатуры.
- [ ] Пройти шесть ручных сценариев и записать результат.
- [ ] Проверить мобильную и широкую компоновку.
- [ ] Выполнить typecheck, тесты и production-сборку.

Критерий приёмки: автоматические проверки зелёные, ручной чеклист заполнен.

## Этап 6. Документация и сдача — 2 часа

- [ ] Встроить содержательный AI Worklog в интерфейс.
- [ ] Дополнить README описанием формулы, запуска, тестов и ограничений.
- [ ] Зафиксировать фактическое время и доступную статистику токенов.
- [ ] Выполнить финальную проверку в чистом/инкогнито-окне.
- [ ] Опубликовать GitHub-репозиторий и приложение.
- [ ] Проверить обе публичные ссылки.

Критерий приёмки: выполнен Definition of Done из спецификации.

## Что не входит в первую версию

- backend и база данных;
- авторизация;
- совместная работа;
- CRUD порталов;
- серверная синхронизация времени и фоновая симуляция при закрытой вкладке;
- сложные анимации и дополнительные библиотеки состояния.
