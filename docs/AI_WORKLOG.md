## Этап 1. Анализ и подготовка репозитория

- Человек: предоставил исходное задание, запросил максимально быстрый реальный
  план, выбрал React Context и CSS Modules.
- AI: прочитал RTF, сравнил варианты, предложил вариант с порталами, сформировал
  спецификацию, архитектуру, план, чеклисты, инструкции для следующих AI-сессий
  и запускаемый каркас.
- Суть промптов: «изучи задание и составь план»; «сократи график до максимально
  быстрого реального срока»; «выбери React Context и CSS Modules, запиши план в
  файл и подготовь репозиторий для AI-driven разработки».
- Решения человека: использовать React Context; использовать CSS Modules;
  подготовить процесс AI-driven разработки до реализации функций.
- Исправления и отклонённые предложения: пятидневный график был заменён на
  реалистичную оценку 12–16 часов. AI также ошибочно сопоставил ответ `npm view`
  для Vite с версией TypeScript; ошибка была обнаружена первой установкой,
  версия перепроверена отдельным запросом и исправлена до продолжения работы.
- Проверки: `npm run typecheck`, `npm run test:run` и `npm run build` успешно
  выполнены; стартовый smoke-тест — 1 из 1 пройден.
- Фактическое время этапа: **заполняется владельцем**.

  статусов до начала реализации.

  долю истёкшего времени и терминальное закрытие после критичного состояния.
- AI сделал: согласовал формулировки между спецификацией, архитектурой, планом и
  чеклистом; явно описал границы диапазонов и математические крайние случаи.
- Суть ключевого промпта: «зафиксируй изменения модели миров и порталов, формулы
  времени и риска и правила статусов».
- Что было принято или изменено вручную: все перечисленные продуктовые правила

## Этап 3. Проект механики стабилизации

- Цель: добавить осмысленные возможности для важных опасных и критичных
  порталов и создать выбор при ограниченном числе попыток.
- Человек сделал: сформулировал критерии важности, потребность в наблюдателе,
  ограничении попыток, случайном результате и запрете уменьшать время жизни;
  отдельно запретил отправку наблюдателя в критичный портал при любых условиях.
- AI сделал: предложил общий лимит три попытки за скользящий час, формулу шанса,
  постоянный случайный бонус к стабильности и три альтернативных алгоритма;
  добавил требования к интерфейсу и тестам.
- Суть ключевого промпта: «добавь возможности для опасных и критических
  порталов и предложи неочевидные алгоритмы стабилизации».
- Что было принято или изменено вручную: продуктовые критерии, инвариант
  безопасной попытки и абсолютный запрет наблюдателя для критичного портала
  заданы человеком; числовые коэффициенты пока не утверждены.
- Где AI ошибся или предложил слабое решение: первоначальный проект AI разрешал
  наблюдателя очень важному критичному порталу; человек исправил это правило.
  Формула вероятности остаётся предложением и требует игрового баланса.
